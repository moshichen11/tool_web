# 策略选股设计

## 目标

将“条件选股”改造为“策略选股”。系统在每个交易日收盘后生成可追溯的研究候选，分别服务短线（1–5 个交易日）与波段（1–4 周）观察。候选不是买卖指令，也不承诺收益。

## 范围与边界

- 股票池仅包含仍上市、可正常交易的 A 股主板股票。
- 排除退市、ST、停牌、科创板、创业板与北交所股票。
- 停牌股票继续在普通股票信息和日 K 功能中可见，但不进入策略候选池。
- 现有日 K 接口、缓存、图表和股票详情页保持不变；策略扫描不写入或替换日 K 数据。
- 首板、炸板回封、跳空追强等依赖分钟/盘口数据的策略不在第一版自动输出。
- 恐慌反转等高不确定策略不在第一版自动输出。

## 免费运行方式

GitHub Actions 在工作日北京时间 16:10 后触发。任务先加载合格主板股票的行情清单，以流动性和当日强度预筛约 600 只，再取得所需日 K 并计算策略。任务将以下静态文件提交到仓库，供 GitHub Pages 直接读取：

- `data/strategy-selection/latest.json`：最近一次有效快照。
- `data/strategy-selection/YYYY-MM-DD.json`：按交易日归档的快照。

快照必须包含交易日、生成时间、数据源、覆盖股票数、预筛数量和状态。休市、行情日期未更新或扫描失败时，任务不得用空结果覆盖 `latest.json`；应保留上次有效快照并写入过期状态与原因。页面据此提示用户数据不是实时结果。

## 候选计算

所有策略先应用股票池、日 K 完整性和流动性过滤。每个命中结果包含策略标识、策略内评分、命中理由、失效条件、风险标签、行业与流动性指标。每个行业默认最多输出两只，短线和波段各显示前十只。

### 短线策略

1. 龙头转强：按行业相对强度、近五日强度、成交额、量能和收盘强度计算代理评分；它不声称识别真实市场龙头。
2. 反包确认：前一日阴线或长上影后，当日实体覆盖前日实体、收盘转强，并有量能确认。
3. 强势回踩转强：近十日表现强势，随后两至八日缩量回撤，当日重新站上短期均线。

### 波段策略

1. 趋势突破：MA5 高于 MA10、MA10 高于 MA20，且放量突破近二十日高点。
2. 趋势回踩：中期均线向上，价格回踩 MA10 或 MA20 后缩量企稳并出现转强 K 线。

策略阈值存放在版本化配置中。输出时记录配置版本，确保旧快照可以解释和复核。

## 页面改造

“条件选股”入口更名为“策略选股”，不再把通用条件组合当作主流程。页面包含：

- 短线候选与波段候选视图；
- 策略说明与数据限制；
- 历史快照浏览；
- 每只候选的评分、命中规则、数据日期、观察价位参考、失效条件、风险标签和流动性信息；
- 当前快照的生成状态、过期状态与失败原因。

点击候选仍复用既有股票详情和日 K 图表。手动刷新只重新载入最近的静态快照，不触发全市场扫描。

## 验证

- 对每个策略提供固定日 K 样本，覆盖命中、不命中和数据不足。
- 验证股票池排除规则、行业限额和短线/波段独立排序。
- 验证快照结构、配置版本、成功覆盖、休市回退与失败不覆盖行为。
- 验证页面状态、风险提示、历史快照加载，以及候选跳转后日 K 正常可用。
- 不以回测结果宣称策略盈利、胜率或提供交易建议。
